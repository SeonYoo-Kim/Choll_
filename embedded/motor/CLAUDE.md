## 세션 시작 시 필수 확인
새 세션에서 이 디렉토리(`motor/`) 작업을 시작하기 전에 반드시 [docs/current.md](docs/current.md)를 먼저 읽고 현재 프로젝트 상태(아키텍처, 완료된 기능, 진행 중인 작업, 다음 목표)를 파악합니다.
`docs/history/` 아래 문서는 기본적으로 읽지 않습니다. `docs/current.md`가 특정 history 문서를 명시적으로 언급하는 경우에만 그 문서를 참고합니다.
이 CLAUDE.md는 작업 규칙만 다루며, 프로젝트 상태는 다루지 않습니다. 프로젝트 상태는 항상 `docs/current.md`가 정본입니다.

## 작업 범위
사용자의 명시적인 요청이 없는 한 이 디렉토리(`motor/`) 하위만 대상으로 작업합니다.

## PinMap
PinMap은 프로젝트의 고정 사항입니다.
사용자의 명시적인 요청이 없는 한 `.ioc`의 Pin 설정 및 주변장치 설정(GPIO, Timer, PWM, UART, SPI, I2C, ADC, DMA, Interrupt 등)을 수정하지 않습니다.
PinMap 변경이 필요하면 자동으로 수정하지 말고 먼저 사용자에게 제안합니다.

## CubeMX
CubeMX 설정은 `.ioc` 파일을 정본으로 사용합니다.
`.ioc` 파일은 사용자의 명시적인 요청 없이 수정하지 않습니다.
자동 생성 코드는 사용자의 요청 없이 수정하지 않습니다.

## 수정 원칙
요청한 기능과 직접 관련된 파일만 수정합니다.
사용자의 요청이 없는 한 불필요한 리팩토링, 파일 이동, 함수 이름 변경, 코드 스타일 변경은 수행하지 않습니다.

## 작업 원칙
가능한 적은 파일만 읽고 수정합니다.
필요한 파일만 확인하며, 불필요하게 상위 디렉토리나 다른 모듈을 탐색하지 않습니다.
확실하지 않은 내용은 추측하지 않습니다.
PinMap, 통신 인터페이스, 하드웨어 구성, 전기적 연결은 확인이 필요한 경우 사용자에게 먼저 질문합니다.

## 문서 유지 원칙
- [docs/current.md](docs/current.md): 항상 현재 상태만 유지합니다. 완료된 기능은 요약만 남기고, 진행 중인 작업만 상세히 작성합니다. 짧게 유지하는 것이 우선순위입니다.
- `docs/history/`: 완료된 기능의 상세 기록(구현 목적, 설계 이유, 검증 과정, 테스트 결과)을 보관합니다. `current.md`에서 상세 내용을 덜어낼 때 그 내용을 여기로 옮깁니다. 파일명은 `YYYY-MM-DD_주제.md` 형식을 사용합니다.
- 기능 구현·설계 변경 등 프로젝트 상태에 영향을 주는 작업을 마치면, 그 변경을 `docs/current.md`에 반영합니다(필요 시 상세 내용은 `docs/history/`에 새 문서로 남기고 `current.md`에서는 요약과 링크만 유지).
